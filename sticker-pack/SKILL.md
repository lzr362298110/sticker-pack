# 照片和角色表情包

先确认需求，再交付提示词。静态母图由用户确认后，才切成 240×240 单格并交付逐格 GIF 提示词。用户可以自行选择静态与动图生成平台。切图和 GIF 尺寸整理脚本需要 Python 3.9+ 和 Pillow 10+。

## 1. 收图与确认需求

- 收到角色原图后，先检查本轮是否有风格参考及文字要求。区分角色图、风格图与待改结果。新任务从本轮材料判断，只有用户明确说沿用时才复用上次的风格、文案、背景或张数。续作以已确认的项目记录为准。
- 有用户上传或选定的图库风格图时，实际查看并向用户说明「图里有什么 → 这套怎么用」。按 [画风反推结构](references/static-planning.md#从参考图提炼可执行的画法) 从整套观感看到局部细节，区分重复出现的画法与单格内容。角色辨识点以原图为准。用户的文字要求优先于参考图。
- 没有风格参考且用户未指定画风时，按角色从 [参考图库](assets/references/catalog.md) 给 2–4 个画风选项，附参考编号、短说明及可用的图片链接或预览。宿主无法展示图库图片时，用参考编号和图库描述给出文字选项。场景从策划索引挑相关选项，例如生活聊天、打工职场、萌宠、情侣或群聊吐槽，并允许自定义或混搭。
- 一轮补齐所有缺项。确认画风、内容场景、要不要配字、张数和静态背景。配字时确认语言、文案由用户提供或代拟，也可选联网找近期热梗。只有用户选了近期热梗才联网核实并附来源。景别会明显改变成图时一并确认。给出 1–4 张选项，建议先做 1 张 1:1 的 3×3 九宫格。每张 9 格。背景可选透明、纯色或小场景。
- 已给过的答案直接采用。用户可以明确把具体选择交给你。若任何必需项仍缺失或未委托，就停在询问阶段，等用户答复后才设计逐格方案、写提示词或调用生图。只传原图或说「做表情包」本身不表示委托选择。

## 2. 先交付静态方案和提示词

偏好明确后，按 [静态提示词与返修模板](references/static-prompts.md) 先给用户看选定参考的借鉴摘要、每张主题和逐格方案。每格说明用途、表情动作、台词与位置。按构图混用气泡、侧边、道具字、顶部或底部，检查跨张动作和文字重复。用户给的台词原样保留。

按 [画风提示词结构](references/static-planning.md#画风提示词结构) 把选定特征转成具体画法，分清整套共用规则与逐格变化。每张九宫格独立交付一条完整提示词，内含相同的画风描述、角色辨识点、背景、画幅与九格指令。静态新图的生图输入只使用用户角色图与文字提示词。风格图、图库图和已出样张留在分析阶段。提示词避免依赖参考图编号、名称、链接或前文。模型专用参数另列。在明确识别为 Codex 且内置生图可用时，需求确认后先展示完整提示词，再用同一版提示词和用户角色图一张一张出图。用户选择只要提示词或先审方案时，遵照该选择。其他宿主交付提示词与角色图上传说明，由用户自行选平台生成。Codex 内置工具未公开底层型号时，如实说明调用路线。

## 3. 收回静态母图并按格返修

- 对照方案检查格数、角色一致性、台词、背景及切分留白。用户回传结果后，用 `02-R2C3` 这类编号定位。只按用户点名的格和改动写一条新版局部编辑提示词，以回传母图为首张编辑参考，列清保持其他格不变的要求。交付局部编辑提示词及所需的回传母图，确需补强辨识度时才加原角色图。画风靠文字描述，风格参考图仅用于分析。其他问题可以单列，留待用户决定是否加入修改范围。
- 多张或跨轮续作按 [交接格式](references/handoff.md) 记录当前版本、目标格与已确认状态。收到回传图本身不表示定稿。等用户明确确认全套当前静态母图后才切图。静态版本变更时，将对应格的旧切图和动图提示词标记为历史。

## 4. 切图并交付 GIF 提示词

- 按 [裁切与导出](references/handoff.md#切分) 确认实际格线及安全留白，再用 [切图脚本](scripts/split_grid.py) 输出 240×240 PNG。按比例缩放、必要时补边，保留透明通道、完整文字和主体。文件名与格号对应。
- GIF 背景在本阶段单独确认。已明确的选择可直接采用。等待 GIF 背景答复时可以先完成已获确认的静态切图，写动图提示词需等答复。按 [动图提示词](references/gif-prompts.md) 给每张 PNG 一条同编号提示词，描述动作、节奏、循环、画面边界与文字固定。选择透明时，每条首句写「生成一个透明背景的循环 GIF」。交付 PNG 和逐格提示词，由用户上传到自选平台生成动图。
- 若用户只回传个别不满意的 PNG 或 GIF，按格号记录反馈。静态画面问题走静态返修。动效问题以确认过的单格 PNG 为起始参考，只重写对应格的 GIF 提示词，明确要改的动作、速度或文字状态。用回传 GIF 定位问题，供用户在原平台重生成。

## 5. 可选的 GIF 上传尺寸整理

用户回传 GIF 并要求整理时，核对所请求范围的格号。要求整包时列出缺失项，要求整理部分文件时只处理对应文件。使用 [GIF 尺寸整理脚本](scripts/resize_gifs.py) 按 [导出说明](references/handoff.md#gif-尺寸整理) 批量输出 240×240 GIF。保留纵横比、已有透明背景、播放节奏和循环设置，检查每张仍能正常播放且文字可读。将整理后的 GIF 单独打包，保留输入原档。宿主无法执行脚本或写文件时，给出本地运行命令及依赖。240×240 是这套流程的画布规格，平台另有体积或审核要求时按用户提供的规范处理。
